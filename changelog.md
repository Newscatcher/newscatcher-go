## v2.0.0 - 2026-04-13
* The following aggregation-related types have been removed from the SDK: `AggregationGetRequest`, `AggregationPostRequest`, `AggregationCountResponseDto`, `FailedAggregationCountResponseDto`, `AggregationGetResponse`, `AggregationPostResponse`, `AggregationBy`, `AggregationItem`, `Aggregations`, `TimeFrameCount`, and all associated visitor interfaces and constructor functions. Consumers using any of these types must remove or replace those usages, as the aggregation endpoint is no longer supported by this SDK.
* **Breaking changes:** The `aggregation` sub-package has been removed, including `aggregation.NewClient()`, `aggregation.Client`, and its `Get`/`Post` methods. All `LatestHeadlines*` request and response types, visitor interfaces, and constructor functions (e.g. `NewLatestHeadlinesGetResponseFromSearchResponseDto`) have also been removed from the root package. Update your code to remove any references to these symbols.
* The `searchlink` package and its `Client` (including `SearchUrlGet` and `SearchUrlPost` methods) have been removed. The associated top-level types `SearchUrlGetRequest`, `SearchUrlPostRequest`, `Ids`, `Links`, `IdsVisitor`, and `LinksVisitor` have also been removed. Callers relying on search-by-link functionality should consult the API documentation for alternative endpoints.
* The following exported types and functions related to the Search Similar API have been removed from the SDK and are no longer available:
* Request types: `SearchSimilarGetRequest`, `SearchSimilarPostRequest`
* Response types: `SearchSimilarResponseDto`, `FailedSearchSimilarResponseDto`, `SimilarArticleEntity`, `SimilarDocument`
* Union response wrappers and visitors: `SearchSimilarGetResponse`, `SearchSimilarPostResponse`, `SearchSimilarGetResponseVisitor`, `SearchSimilarPostResponseVisitor`
* Enum types: `SearchSimilarGetRequestPublishedDatePrecision`, `SearchSimilarGetRequestSortBy`
* Type aliases: `IncludeSimilarDocuments`, `SimilarDocumentsFields`, `SimilarDocumentsNumber`
* Consumers using any of these symbols must remove those references; no replacement types are provided in this release.
* The `searchsimilar` package has been removed from the SDK. The `searchsimilar.Client`, `searchsimilar.NewClient()`, `Client.Get()`, and `Client.Post()` symbols no longer exist. Consumers who imported `github.com/Newscatcher/newscatcher-go/searchsimilar` must remove those imports and calls; consult the API documentation for any replacement functionality.
* Several exported types in the authors API have been renamed for consistency: `AuthorsGetRequest` is now `GetAuthorsRequest`, `AuthorsPostRequest` is now `PostAuthorsRequest`, `AuthorsGetResponse` is now `GetAuthorsResponse`, `AuthorsPostResponse` is now `PostAuthorsResponse`, and the corresponding visitor interfaces have been renamed accordingly. The `AuthorsGetRequestPublishedDatePrecision` and `AuthorsGetRequestSortBy` enum types have been removed in favour of the shared `PublishedDatePrecision` and `SortBy` types. The `NewAuthorsGetResponseFrom*` and `NewAuthorsPostResponseFrom*` constructor functions have been removed. Additionally, `From`/`To` date fields and several primitive filter fields now use typed wrappers instead of `*time.Time` or `*int`/`*bool`/`*float64`. A new `AllLinksText` filter field and `Set*` helper methods have been added to all affected structs.
* **Breaking changes in the `authors` package:**
* The request types `AuthorsGetRequest` and `AuthorsPostRequest` have been renamed to `GetAuthorsRequest` and `PostAuthorsRequest`.
* The response types `AuthorsGetResponse` and `AuthorsPostResponse` have been renamed to `GetAuthorsResponse` and `PostAuthorsResponse`.
* The `NewClient` constructor now accepts a single `*core.RequestOptions` argument instead of variadic `option.RequestOption` values — update call sites accordingly.
* A new `WithRawResponse` field (`*RawClient`) is now available on the `Client` struct, allowing access to the raw HTTP response for each API call.
* Several search types have been renamed and their field types changed, which is a breaking change for existing consumers.
* `SearchGetRequest` is now `GetSearchRequest` and `SearchPostRequest` is now `PostSearchRequest` (and vice-versa for their response and visitor types).
* `SearchGetResponseVisitor` is now `GetSearchResponseVisitor`; `SearchPostResponseVisitor` is now `PostSearchResponseVisitor`.
* The previously exported enum types `SearchGetRequestClusteringVariable`, `SearchGetRequestNewsDomainType`, `SearchGetRequestPublishedDatePrecision`, and `SearchGetRequestSortBy` (along with their `NewXxxFromString` and `.Ptr()` helpers) have been removed; use the shared package-level equivalents instead.
* Many `GetSearchRequest` fields have changed from primitive types (`*time.Time`, `*int`, `*float64`, `*bool`) to named alias types.
* Migrate by updating all type references in your code to the new names and replacing direct field assignments with the new `SetXxx` methods where explicit null/zero serialisation is required.
* The `NewClient` constructor in the `sources` and `subscription` packages now accepts a `*core.RequestOptions` value instead of variadic `...option.RequestOption`; update call sites to pass `core.NewRequestOptions(opts...)` explicitly. The request types `SourcesGetRequest` and `SourcesPostRequest` have been renamed to `GetSourcesRequest` and `PostSourcesRequest` respectively. Each client now exposes a `WithRawResponse` field for accessing raw HTTP responses, and `SubscriptionResponseDto` gains explicit-field setters (`SetActive`, `SetPlan`, etc.) that control JSON serialization of zero-value fields.
* Several exported fields on the top-level `Client` struct have been renamed or removed. Callers must update field references: `Latestheadlines` is now `LatestHeadlines`, `SearchLink` is now `SearchByLink`, `Aggregation` is now `AggregationCount`, and `Searchsimilar` has been removed with no replacement. Additionally, retry behavior has changed significantly—minimum retry delay increased from 500ms to 1s and maximum from 5s to 60s—and datetime deserialization now accepts Unix epoch integers, RFC3339Nano, ISO 8601 without timezone, and date-only strings in addition to RFC3339.
* The SDK now supports the **Aggregation Count** endpoint, allowing consumers to retrieve article counts grouped by time interval (day, hour, or month). New types include `GetAggregationCountRequest`, `PostAggregationCountRequest`, `AggregationBy`, `AggregationCountResponseDto`, `FailedAggregationCountResponseDto`, `AggregationItem`, and `TimeFrameCount`, along with visitor interfaces for type-safe union response handling.
* The SDK now includes a new `aggregationcount` package with `Get` and `Post` methods for retrieving article counts aggregated by day or hour. All resource clients now expose a `WithRawResponse` field (a `RawClient`) that returns a `core.Response[T]` containing the raw HTTP status code and headers alongside the parsed body. A new top-level `ErrorCodes` variable enables typed error handling for HTTP 400, 401, 403, 408, 422, 429, and 500 responses.
* The SDK now exposes `GetLatestHeadlinesRequest` and `PostLatestHeadlinesRequest` structs along with their union response types (`GetLatestHeadlinesResponse` and `PostLatestHeadlinesResponse`) for the latest-headlines endpoints. Both request types include typed `Set*` helper methods that ensure explicitly-set fields are always serialized, even when their value is empty or null.
* The SDK now includes a `searchbylink` package with `Get` and `Post` methods for searching articles by article link or Newscatcher article ID. All sub-packages (`search`, `latestheadlines`, `sources`, `subscription`) now also expose a `RawClient` (accessible via `client.WithRawResponse`) that returns the full HTTP status code and response headers alongside the decoded body. New union types `Ids` and `Links` support either a single string or a list of strings when calling the search-by-link POST endpoint.
