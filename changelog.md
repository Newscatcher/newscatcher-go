## v2.0.0 - 2026-03-16
* The entire aggregation module has been removed from the SDK. All aggregation-related types, request structures, and response models are no longer available. Applications using aggregation functionality must be refactored to use alternative approaches.
* The aggregation package and latest headlines functionality have been removed from the SDK. Applications using `aggregation.Client` or latest headlines request/response types will need to be updated to use alternative endpoints.
* The search by link functionality has been removed from the SDK. This includes the `searchlink.Client` with its `SearchUrlGet()` and `SearchUrlPost()` methods, along with related types `SearchUrlPostRequest`, `SearchUrlGetRequest`, `Ids`, and `Links`. Applications using these APIs must migrate to alternative search methods.
* The SearchSimilar functionality has been completely removed from the SDK. All SearchSimilar-related methods, types, and data models are no longer available. Applications using SearchSimilar features will need to be updated to use alternative search methods or contact support for migration guidance.
* The `searchsimilar` package has been removed entirely. This includes the `searchsimilar.Client` type and its `Get()` and `Post()` methods. Code that imports or uses this package will need to be updated to use alternative functionality.
* Breaking changes to authors API request types. The `AuthorsGetRequest` type has been renamed to `GetAuthorsRequest` and `AuthorsPostRequest` to `PostAuthorsRequest`. Additionally, many parameter fields now use dedicated type aliases instead of primitive types, which may require type casting in some usage patterns. New `AllLinksText` field is now available for searching articles by link anchor text.
* The authors client constructor signature has changed from `NewClient(opts ...option.RequestOption)` to `NewClient(options *core.RequestOptions)`. Replace variadic option calls with `core.NewRequestOptions(opts...)`. The client now includes a `WithRawResponse` field for accessing raw HTTP responses.
* Breaking changes to breaking news request types: `BreakingNewsGetRequest` has been renamed to `GetBreakingNewsRequest` and `BreakingNewsPostRequest` has been renamed to `PostBreakingNewsRequest`. Update your code to use the new type names. The `Content` field in `BreakingNewsArticleEntity` is now optional (pointer type). The `Authors` and `Journalists` fields now use specific union types instead of generic types.
* Breaking changes: The SDK has been migrated to a new v505 module structure. Update import paths from `github.com/Newscatcher/newscatcher-go` to `github.com/Newscatcher/newscatcher-go/v505`. Client constructors now require `*core.RequestOptions` instead of variadic options - use `core.NewRequestOptions()` to create the options struct. The breaking news client methods have been renamed from `BreakingNewsGet`/`BreakingNewsPost` to `Get`/`Post`. All clients now include a `WithRawResponse` field for accessing HTTP response headers and status codes.
* Breaking changes to search API types: `SearchGetRequest` renamed to `GetSearchRequest`, `SearchPostRequest` renamed to `PostSearchRequest`, and response types updated accordingly. Parameter types changed from primitives to type aliases (e.g., `*int` to `*FromRank`). Existing code using these types will need to update import statements and type references.
* The SDK has been restructured with breaking changes to package imports and client initialization. All imports now use the v505 versioned namespace (e.g., `github.com/Newscatcher/newscatcher-go/v505`). Client constructors now accept a single `*core.RequestOptions` parameter instead of variadic options. A new `WithRawResponse` client is available for accessing raw HTTP responses alongside parsed data.
* Breaking change: Client constructors now require `*core.RequestOptions` instead of accepting variadic `option.RequestOption` parameters. Update client initialization from `NewClient(opts...)` to `NewClient(options)` where `options` is a `*core.RequestOptions` instance. All import paths have been updated to use the v505 package structure. Method signatures and return types remain unchanged.
* The SDK now supports searching articles by link anchor text with the new `AllLinksText` parameter. When this parameter is used, the response includes detailed link information in the `AllLinksData` field. Additionally, all struct types now provide `SetX()` methods for explicit field control during JSON serialization.
* New aggregation count API endpoints enable retrieval of time-based article count statistics. The SDK now supports querying article publication patterns across day, hour, and month intervals with comprehensive search filtering options.
* New aggregation count client available with methods to retrieve article counts aggregated by day or hour. Enhanced HTTP response handling across all clients with structured response types and improved error handling.
* New latest headlines endpoint support with extensive filtering options including language, country, source, content analysis, and NLP data parameters. Both GET and POST methods are available with support for clustered and standard search responses.
* New RawClient available for all endpoint modules, providing access to raw HTTP responses. Added searchbylink module for searching articles by ID or URL. Added Bytes() utility function for creating pointers to byte slices.
