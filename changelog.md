## v2.0.0 - 2026-04-13
* The following aggregation-related types have been removed from the SDK: `AggregationGetRequest`, `AggregationPostRequest`, `AggregationCountResponseDto`, `FailedAggregationCountResponseDto`, `AggregationItem`, `Aggregations`, `TimeFrameCount`, `AggregationBy`, `AggregationGetResponse`, `AggregationPostResponse`, and all associated visitor interfaces and constructor functions. Consumers using any of these types must remove or replace those references, as the aggregation API surface is no longer available in this version of the SDK.
* Several exported symbols have been removed from the SDK. The entire `aggregation` sub-package (`aggregation.Client`, `aggregation.NewClient`, and its `Get`/`Post` methods) has been deleted. The following top-level types have also been removed: `LatestHeadlinesGetRequest`, `LatestHeadlinesPostRequest`, `LatestHeadlinesGetResponse`, `LatestHeadlinesPostResponse`, their associated visitor interfaces, the `LatestHeadlinesGetRequestClusteringVariable` enum and constants, and the `When` type alias. Callers referencing any of these symbols must update their code accordingly.
* The `searchlink` package and all related search-by-link types have been removed from the SDK. Consumers using `searchlink.Client.SearchUrlGet`, `searchlink.Client.SearchUrlPost`, or the associated request/union types (`SearchUrlGetRequest`, `SearchUrlPostRequest`, `Ids`, `Links`, etc.) must remove or replace those references. Please consult your Newscatcher API documentation for the updated approach to searching by link or ID.
* The Search Similar API has been removed from the SDK. The following exported types are no longer available: `SearchSimilarGetRequest`, `SearchSimilarPostRequest`, `SearchSimilarResponseDto`, `FailedSearchSimilarResponseDto`, `SimilarArticleEntity`, `SimilarDocument`, `SearchSimilarGetResponse`, `SearchSimilarPostResponse`, and related enums and type aliases. Remove any references to these types in your code or pin to the previous SDK version until the Search Similar API is reinstated.
* The `searchsimilar` package has been removed from the SDK. Code that imports `github.com/Newscatcher/newscatcher-go/searchsimilar` or calls `searchsimilar.NewClient()`, `(*Client).Get()`, or `(*Client).Post()` will no longer compile. Please remove any references to this package and consult the Newscatcher API documentation for alternative endpoints.
* Several types in the authors API have been renamed and restructured. `AuthorsGetRequest`, `AuthorsPostRequest`, `AuthorsGetResponse`, and `AuthorsPostResponse` have been renamed to `GetAuthorsRequest`, `PostAuthorsRequest`, `GetAuthorsResponse`, and `PostAuthorsResponse` respectively. The `AuthorsGetRequestPublishedDatePrecision` and `AuthorsGetRequestSortBy` enums have been removed in favor of shared `PublishedDatePrecision` and `SortBy` types. Many fields that previously used Go primitives (e.g. `*int`, `*bool`, `*time.Time`) now use named type aliases. All request and response structs gain a new `SetXxx()` method pattern for explicit field serialization control, and a new `AllLinksText` field has been added to author search requests.
* The `authors` client has breaking changes in this release. The request and response types have been renamed: `AuthorsGetRequest` → `GetAuthorsRequest`, `AuthorsGetResponse` → `GetAuthorsResponse`, `AuthorsPostRequest` → `PostAuthorsRequest`, and `AuthorsPostResponse` → `PostAuthorsResponse`. Additionally, the `NewClient` constructor signature has changed from a variadic `option.RequestOption` parameter to a single `*core.RequestOptions` argument. Callers must update type references and constructor calls accordingly. A new `WithRawResponse` field is now available on the `Client` struct for accessing raw HTTP responses.
* Several breaking changes have been made to the breaking news API types. `BreakingNewsGetRequest` has been renamed to `GetBreakingNewsRequest` and `BreakingNewsPostRequest` to `PostBreakingNewsRequest`. The `BreakingNewsArticleEntity.Content` field has changed from `string` to `*string` (callers must now dereference the pointer). The `BreakingNewsGetRequestSortBy` enum and its constants have been removed in favor of the shared `SortBy` type, `TopNArticles` has been renamed to `TopNarticles`, and the `RobotsCompliant` field has been removed from request and article entity types. Constructor functions `NewBreakingNewsArticleEntityAllDomainLinksFrom*` and `NewBreakingNewsArticleEntityAllLinksFrom*` have been removed. New `Set*` methods are available on all major types to explicitly mark optional fields for serialization, and `TitleTranslatedEn`/`ContentTranslatedEn` fields have been added to `BreakingNewsArticleEntity`.
* Several search-related types have been renamed for consistency: `SearchGetRequest` is now `GetSearchRequest`, `SearchPostRequest` is now `PostSearchRequest`, `SearchGetResponse` is now `GetSearchResponse`, and `SearchPostResponse` is now `PostSearchResponse`. The visitor interfaces `SearchGetResponseVisitor` and `SearchPostResponseVisitor` are likewise renamed to `GetSearchResponseVisitor` and `PostSearchResponseVisitor`. Request-scoped enum types (`SearchGetRequestSortBy`, `SearchGetRequestClusteringVariable`, `SearchGetRequestNewsDomainType`, `SearchGetRequestPublishedDatePrecision`) and their constructor/Ptr helpers have been removed and replaced with shared package-level types. The `From` and `To` fields on `GetSearchRequest` have changed from `*time.Time` to the `*From` and `*To` named types, and many other fields now use named type aliases instead of raw primitives. Constructor helpers `NewSearchGetResponseFrom*` and `NewSearchPostResponseFrom*` have been removed. A new `AllLinksText` field is available on both request types, and all request fields now have corresponding `Set*` methods for explicit null-safe serialization.
* The `NewClient` constructor in the `sources` and `subscription` packages now accepts a `*core.RequestOptions` value instead of variadic `option.RequestOption` options — callers must wrap their options with `core.NewRequestOptions(...)`. The request types `SourcesGetRequest` and `SourcesPostRequest` have been renamed to `GetSourcesRequest` and `PostSourcesRequest` respectively. A new `WithRawResponse` field is available on both clients for accessing raw HTTP responses alongside parsed bodies. `SubscriptionResponseDto` now exposes explicit field setters (`SetActive`, `SetPlan`, etc.) and a `MarshalJSON` method that preserves zero-value fields when explicitly set.
* Several exported fields on the top-level `Client` struct have been renamed or removed. Callers must update field references as follows: `Latestheadlines` → `LatestHeadlines`, `SearchLink` → `SearchByLink`, `Aggregation` → `AggregationCount`. The `Searchsimilar` field has been removed with no direct replacement on `Client`. The underlying packages `searchlink`, `searchsimilar`, and `aggregation` are replaced by `searchbylink` and `aggregationcount` — update any direct package imports accordingly. Additionally, retry behavior now honours `Retry-After` and `X-RateLimit-Reset` response headers, uses a wider default delay window (1 s – 60 s), and datetime fields now accept Unix epoch integers, fractional-second RFC3339, timezone-less ISO 8601, and date-only strings.
* The SDK now supports the **Aggregation Count** endpoint. Use the new `GetAggregationCountRequest` / `PostAggregationCountRequest` types to query article counts aggregated by day, hour, or month, and inspect results via `AggregationCountResponseDto` and the `AggregationBy` enum. All existing search filter parameters (language, country, NLP, sentiment, IPTC tags, etc.) are available on the new request types.
* The SDK now includes a new `aggregationcount` package with `Client` and `RawClient` for retrieving article counts aggregated by day or hour. A new generic `core.Response[T]` type is available across all raw clients, giving consumers direct access to HTTP status codes and response headers. Additionally, `RawClient` variants have been added to the `authors` and `breakingnews` packages, and a top-level `ErrorCodes` variable now provides typed error handling for standard HTTP error responses (400, 401, 403, 408, 422, 429, 500).
* The SDK now includes `GetLatestHeadlinesRequest`, `PostLatestHeadlinesRequest`, `GetLatestHeadlinesResponse`, and `PostLatestHeadlinesResponse` types for the Latest Headlines API endpoints. Both request types support explicit field tracking via `Set*` methods, ensuring that null or zero values are included in serialized output when intentionally set. Response types expose a visitor pattern for handling the union of `SearchResponseDto` and `ClusteredSearchResponseDto` results.
* The SDK now includes a new `searchbylink` package with `Get` and `Post` methods for searching articles by article link or ID. Raw response clients (`RawClient`) are also now available on the `latestheadlines`, `search`, `sources`, and `subscription` packages, providing access to HTTP status codes and response headers in addition to the decoded response body. New supporting types `GetSearchByLinkRequest`, `PostSearchByLinkRequest`, `Ids`, and `Links` are available in the root package.
